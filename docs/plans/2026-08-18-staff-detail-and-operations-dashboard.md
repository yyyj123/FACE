# 技师详情页与运营数据看板实施计划

## 目标

- 用户端首页技师卡片仅展示照片、姓名、职级和查看详情入口，避免长技能文本撑高卡片。
- 新增响应式技师详情页，集中展示个人介绍与全部擅长项目，并提供预约入口。
- 运营管理平台首页改为真实经营数据驱动的 ECharts 看板，移除技术栈和迁移检查信息。

## 实施范围

1. 在 `front-next` 增加 `/staff/:id` 路由和详情页；首页卡片改为可点击摘要卡片。
2. 复用现有公开技师接口；详情页按门店公开列表匹配技师，不暴露停用或非本店员工。
3. 在 `admin-next` 接入现有 `/api/v3/analytics/sales/overview`，提供门店和统计周期筛选。
4. 用 ECharts 展示实收与订单趋势、项目类型构成、护理项目排行、品类构成和门店对比；无数据时显示明确空状态。
5. 增加静态契约测试，完成两端测试与构建；重建演示容器并记录验证证据。

## 验收标准

- 技师列表不再直接展示完整技能长文本；鼠标、触屏和键盘均可进入详情。
- 技师详情支持桌面与手机宽度，数据不存在时有可返回的错误状态。
- 运营总览不再出现 Java、MySQL、Flyway 等技术信息。
- 图表数据来自现有经营分析接口，切换门店或周期后重新请求；加载、失败和空数据状态完整。
- `front-next`、`admin-next` 测试和生产构建通过；演示容器健康。
