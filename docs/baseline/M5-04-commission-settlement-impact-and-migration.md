# M5-04 提成结算批次影响与迁移说明

## 1. 当前任务与验收

- 阶段：M5-04。
- 输入：四份 V1.2 商业基线、M5 生命周期/API 契约、M5-02 规则快照、M5-03 不可变提成流水。
- 输出：结算批次、不可变结算明细、计算/确认/支付/关闭/整批作废、财务核对字段和技师本人摘要。
- 验收：只有 `FROZEN` 且未进入有效批次的流水可结算；一个流水最多进入一个有效批次；创建/计算者不能确认本人批次；确认后明细不可覆盖；支付和关闭只追加事实；已支付/已关闭不可作废或重开；汇总可由明细复算；所有关键写有权限、版本、幂等、审计和 outbox。

## 2. 影响模块、表、接口、权限和状态

- `settlement` 新模块独占 `commission_settlement_batch`、`commission_settlement_item`。
- `commission` 只通过公开应用服务把 `FROZEN` 流水转为 `SETTLED`，结算模块不得改金额、规则版本或来源快照。
- 新增权限：
  - `commission:settlement:view`
  - `commission:settlement:manage`
  - `commission:settlement:approve`
- 新增 `/api/v3/commission/settlements` 查询与关键写路由，以及技师 SELF 摘要。
- 批次状态：
  - `DRAFT -> CALCULATED -> CONFIRMED -> PAID -> CLOSED`
  - `DRAFT/CALCULATED/CONFIRMED -> VOIDED`
  - `PAID/CLOSED/VOIDED` 不可重开。
- 提成流水只允许 `FROZEN -> SETTLED`；确认批次后整批作废时只把该批次仍为 `SETTLED` 的流水恢复为 `FROZEN`，金额和历史不变。

## 3. 迁移、索引与历史兼容

计划新增：

- `commission_settlement_batch`：批次号、周期、币种、汇总、状态、版本、各阶段责任人/时间、支付参考、安全原因。
- `commission_settlement_item`：批次、提成流水、员工、结算时金额与发生时间快照、有效标志。

关键数据库能力：

- 租户/门店/结算号唯一。
- 周期起止、金额、计数、版本、状态使用 CHECK 约束。
- 结算明细使用生成列 `active_entry_id` 与唯一索引，保证一个提成流水最多进入一个有效批次，同时允许已作废批次保留历史明细。
- 批次/明细外键不级联删除；已确认明细禁止应用层覆盖。
- 新权限只显式授予 OWNER/MANAGER/FINANCE；技师只通过现有 SELF 查询能力查看本人摘要。

兼容策略：

- Expand-only，不修改 M0-M5-03 表的已有列，不回填或伪造历史结算。
- 历史 `FROZEN` 流水由授权用户显式创建和计算批次；不自动标记已支付。
- `/api/v1`、`/api/v2` 保持不变。

## 4. 职责分离、事务与回滚

- 创建人或最后计算人不能确认批次；服务端以账号标识强制校验，前端隐藏不作为安全边界。
- 计算时锁定候选提成并写明细/汇总；唯一索引处理并发争用。
- 确认时同一事务锁定批次和全部有效明细，验证流水仍为 `FROZEN` 后转为 `SETTLED`，写历史、审计与 outbox。
- 支付只记录支付事实和安全参考，不保存银行卡、账号或支付凭据。
- 整批作废不删除明细；将 `active_flag` 置 0，必要时恢复流水为 `FROZEN` 并追加历史。
- 回滚先关闭结算写路由，保留新表只读；已经确认、支付或关闭的批次不得物理删除，后续差额进入新批次。

## 5. 测试先行清单

1. 状态机合法路径、非法跳转、终态不可重开。
2. 创建/计算者确认本人批次被拒绝。
3. 仅 `FROZEN` 流水可计算，一个流水并发进入两个有效批次被拒绝。
4. 汇总等于明细金额之和，负向冲正保留方向。
5. 确认后明细不可覆盖；整批作废保留历史并释放有效占用。
6. 版本冲突、同键异载荷和重放幂等。
7. 管理/财务范围、技师 SELF、跨门店/跨租户拒绝。
8. 新鲜 MySQL 8 迁移、约束、事务、全历史链、全量测试和构建。
