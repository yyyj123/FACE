# M6-10 Docker 部署影响、迁移与回滚说明

## 开工检查

1. 当前阶段与任务：M6-10，补齐本地商用基线的 Docker 可部署能力。
2. 输入：M6-09 已验收代码、PRD V1.3、数据库 V1.3、API V1.3、实施与验收 V1.3。
3. 输出：后端、管理端、客户端/技师端和 MySQL 的可复现容器编排，以及真实启动验收记录。
4. 验收：Compose 配置解析、镜像构建、MySQL 基础库初始化、Flyway 全量迁移、后端 readiness、登录接口、两个前端页面和容器健康状态全部通过。
5. 数据库影响：不新增或修改表；MySQL 首次启动先加载已验收的单店基础结构，再由现有 Flyway 迁移到 `2026080103`。生产历史库仍按受控备份、`flyway validate`、迁移和回滚流程执行。
6. 测试顺序：先运行部署契约测试并确认因缺少 Docker 资产失败，再实现编排并复测；最后执行真实容器冒烟。
7. 文档同步：更新最终验收报告、部署说明和源码快照。

## 影响模块

| 模块 | 影响 | 兼容策略 |
| --- | --- | --- |
| `backend-next` | 新增多阶段镜像构建、容器健康检查 | 继续使用现有 `DB_*`、`SERVER_PORT`、`CORS_ALLOWED_ORIGINS` 环境变量，不改 Java 接口 |
| `admin-next` | 构建静态资源并由 Nginx 提供；同源反向代理 `/face-next` | Docker 构建时把 API 基址设为 `/face-next`，本地 Vite 行为不变 |
| `front-next` | 构建客户端/技师端静态资源并由 Nginx 提供 | 沿用相对 API 路径，本地 Vite 行为不变 |
| MySQL | 新容器卷承载数据，首次启动加载 `docs/database/face_salon_mysql8.sql`，随后由 Flyway 迁移 | 不映射数据库公网端口；密码仅由未提交的环境文件注入；不修改历史迁移校验和 |
| 运维 | 新增 Compose、健康检查、资源限制与验收脚本 | 容器使用命名卷，`down` 默认不删除数据；显式 `down -v` 才清空测试卷 |

## 安全与权限

- Compose 文件不保存真实密码；通过 `--env-file .env.docker` 注入。
- 数据库仅在内部网络可见，应用账号只获得目标数据库权限。
- 管理端和客户端只反向代理应用上下文，不暴露 MySQL。
- 健康检查不输出手机号、健康信息、支付凭据或数据库密码。
- 生产环境必须另行配置 TLS、可信反向代理、密钥托管、备份加密和监控告警。

## 迁移方案

1. 先对历史库做全量备份和 SHA-256 校验。
2. 在同版本 MySQL 临时实例恢复备份，执行现有 Flyway `validate/migrate`。
3. 验证最新版本为 `2026080103`、数据库契约健康、核心汇总一致。
4. 灰度切换应用流量；原应用和数据库保留至观察期结束。

## 回滚方案

- 应用回滚：停止新 Compose 服务，恢复上一版镜像或原宿主机服务。
- 数据回滚：停止写入后，从切换前备份恢复到新实例，再按审计记录补偿观察期内业务；禁止直接删除迁移记录或人工反向修改业务表。
- Docker 测试回滚：`docker compose --env-file .env.docker down -v --remove-orphans` 仅用于合成测试环境。
