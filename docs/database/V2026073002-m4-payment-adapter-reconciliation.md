# V2026073002 M4 支付适配与对账迁移说明

## 变更范围

迁移文件：`backend-next/src/main/resources/db/migration/V2026073002__m4_payment_adapter_reconciliation.sql`

### 扩展表

`payment_transaction` 新增通道、外部交易编号、通道状态、通道响应时间和回调版本字段，用于保存可核对的外部支付状态。

### 新增表

- `payment_callback_event`：保存回调事件、防重放键、验签/处理状态和请求摘要。
- `reconciliation_batch`：保存门店、通道、账务日期、系统/通道汇总、状态和乐观锁版本。
- `reconciliation_item`：保存缺单、金额不一致、状态不一致等差异证据。
- `reconciliation_resolution`：只追加差异处理记录，不覆盖原差异。

### 权限

新增 `reconciliation:view` 与 `reconciliation:manage`，并按既有角色权限模型授权。

## 索引与约束

- `(channel_code, channel_event_id)` 唯一约束阻止回调重放。
- `(tenant_id, shop_id, channel_code, accounting_date)` 唯一约束阻止同门店同通道同账务日重复批次。
- 外部交易编号、批次查询、差异批次和处理记录均有定向索引。
- 金额、笔数、状态和版本字段均使用数据库非空、检查或枚举约束。
- 外键使用租户内业务主键关系；历史证据不使用级联删除。

## 兼容策略

- 新列允许历史支付记录为空，既有 CASH/BALANCE 数据无需回填通道编号。
- 旧 V2 路由保持地址兼容，但外部支付不能再通过旧本地成功路径绕过适配器。
- 新表为旁路增量结构，不修改既有不可变流水语义。
- Flyway 按版本前向执行；不得修改已经发布环境中的迁移校验和。

## 回滚策略

1. 应用回滚到不暴露 M4-06 路由的版本，停止支付回调和新建对账批次。
2. 保留新增表和通道列只读，禁止直接删除，以免丢失回调、防重放和对账证据。
3. 如必须清理结构，先导出四张新增表、外部交易编号和 Flyway 历史，核对无待处理支付/退款后再执行独立 DBA 回滚脚本。
4. 任何业务资金纠正均通过退款/冲正应用服务完成，不通过删除迁移或手改金额回滚。

- MySQL 8 空库从基线迁移到 `2026073002` 成功。
- 迁移契约：4 张新增表、5 个支付通道字段、2 个权限全部存在。
- 回调唯一约束、对账唯一约束、版本并发和状态机均已通过自动化验收。
