# M6-06 营销治理模块边界与生命周期

## 1. 业务目标与非目标

本模块帮助店长以“会员本人授权 → 活动提交 → 异岗审批 → 执行时冻结受众 → 站内投递 → 账本审计”的链路完成可核验触达，降低未经同意营销、误发、重复发送和伪造外部送达状态的风险。

当前非目标：自动画像、健康/护理数据分群、短信/邮件/微信真实发送、自动重试外部供应商、群发导入和由管理端代会员勾选授权。

## 2. 模块职责

| 模块 | 责任 | 输入/输出 | 失败行为 | 验证 |
|---|---|---|---|---|
| marketing | 活动、状态历史、同意当前水位/历史、受众和投递账本 | 安全活动字段、会员最小标识、投递结果 | 状态/版本/职责/受众不满足即 4xx 并回滚 | 策略、迁移契约、隔离 API |
| member | 解析本人会员 ID，提供有效会员与账号最小标识 | `memberId + recipientAccountId` | 非会员本人 403；无有效关系不返回候选 | 本人同意与受众适配器 |
| notification | 写入安全站内通知 | 标题、摘要、动作路径、事件 ID | 草稿不安全或重复写入时抛错，触发执行事务回滚 | 实际会员收件箱与唯一键 |
| outbox | 写领域事件业务标识 | `campaignId/memberId` | 载荷含非标识字段时拒绝 | 事件载荷守卫 |
| security | 门店权限与本人范围 | 服务端租户、账号、门店 | 越权 403/404 | 跨门店与职责分离验收 |

## 3. 生命周期与事务

```text
DRAFT -> PENDING_APPROVAL -> APPROVED -> RUNNING -> COMPLETED
   |             |               |
   +-------------+---------------+-> CANCELLED
                 +-> REJECTED
```

执行活动必须持有 `marketing:execute`，活动为 `APPROVED`、版本匹配、通道为 `IN_APP` 且计划时间已到。服务先从会员端口取得最小候选标识，再在营销模块内按当前 `GRANTED` 水位筛选；无符合者返回 409。符合者在同一数据库事务中写入受众快照、outbox、站内通知和投递账本，最后进入 `COMPLETED`。任何异常都会回滚，不留下部分送达或伪完成。

## 4. 数据与隐私边界

- 受众快照仅保存会员 ID、收件账号 ID、同意记录 ID/版本和冻结时间；
- 投递账本仅保存活动/受众/会员/账号标识、通道、状态、事件 ID、次数、稳定错误码和时间；
- 同意文本以服务端版本和哈希固定；当前水位可更新，历史表只新增不覆盖；
- 缺少同意记录等同未同意，迁移不回填 `GRANTED`；
- 不根据肤质、健康、护理、消费明细或支付信息建立营销分群。

## 5. 运营与回退

上线前必须确认 Flyway 最新版本 `2026080102`、四项权限授权、管理端菜单和会员端偏好页可用。应用回退时优先下线路由和菜单，新表保留只读，禁止删除活动、同意、受众、投递和审计事实。外部通道只有在单独完成供应商、回执、退订、重试、隐私和成本验收后才能启用。
