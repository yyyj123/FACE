# FACE V2 库存中心

## 目标

库存中心把旧系统中“商品表库存数量”和“独立出库记录”升级为可供连锁门店使用的库存账：

- 每个库存地点都有实时余额、冻结数量和乐观锁版本。
- 每次库存变化都生成不可修改的流水。
- 待审核调拨先冻结库存，批准后才同时完成调出和调入。
- 商品订单在最后一笔收款完成时自动扣库；扣库失败会回滚整笔收款。
- 所有查询和写操作都从登录令牌推导租户及门店范围。

## 数据结构

Flyway `V2026072406__inventory_center_foundation.sql` 增加或启用：

- `stock_location`：门店主仓、护理耗材间和后续总部仓。
- `stock_balance`：地点与商品维度的账面、冻结和可用库存。
- `inventory_movement`：期初、历史出库、采购、销售、领用、退货、调拨和盘点流水。
- `inventory_transfer`：调拨单头、状态、审核人与并发版本。
- `inventory_transfer_item`：调出商品、调入同 SKU 商品与数量。
- `sales_order.inventory_deducted_at`：订单是否已完成库存扣减的事务标记。

旧 `peijianchuku` 的 5 条记录重建为历史出库流水。迁移先计算“当前库存 + 历史出库”作为期初，再依次扣减历史记录，因此迁移完成后的余额仍与商品表原有库存一致。

## 接口

基础路径：`/face-next/api/v2/inventory`

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/` | 商品库存、各地点余额、冻结和低库存摘要 |
| GET | `/resources` | 可访问库存地点和当前门店商品 |
| GET | `/movements` | 按商品和类型查询不可变流水 |
| POST | `/adjustments` | 采购、退货、领用、其他出入库或盘点调整 |
| GET | `/transfers` | 查询当前门店相关调拨 |
| POST | `/transfers` | 创建调拨并冻结调出库存 |
| POST | `/transfers/{id}/decision` | 批准或拒绝调拨 |

所有写请求使用幂等键；库存余额和调拨单使用 `version` 防止并发覆盖。

## 业务边界

- 调拨支持同店不同库存地点，也支持跨店。跨店时调入门店必须存在相同 SKU 商品。
- 退款不自动回库。退款是资金动作，只有实物验收后才通过“退货入库”登记库存。
- 待审核调拨只增加 `quantity_reserved`，不改变账面库存。
- 批准调拨会在同一事务中减少调出余额、增加调入余额并写入两条流水。
- 拒绝调拨只释放冻结数量。
- 订单未完全收款时不扣库存；变为 `PAID` 时在收款事务内扣减主仓库存。

## 验收

```powershell
$env:FACE_ADMIN_PASSWORD = "<管理员密码>"
npm run verify:inventory
Remove-Item Env:FACE_ADMIN_PASSWORD
```

脚本覆盖入库幂等、旧版本冲突、库存不足、调拨冻结、批准、拒绝、审核冲突、订单支付扣库、缺货收款整体回滚、越权门店和验收后余额恢复。
