# M6-11 公网客户门户热修复影响与回滚说明

## 开工检查

1. 当前阶段与任务：M6-11，修复临时公网部署下会员注册 403、公开项目目录 500 和首页级联空白。
2. 输入：PRD、数据库设计、API 清单、分阶段实施与验收 V1.3，M6-10 Docker 基线及当前代码。
3. 输出：公开目录兼容修复、可信反向代理同源识别、注册输入校验、首页分区容错和回归测试。
4. 验收：后端完整测试、前端单元测试、三端构建、Docker 契约、公开接口与浏览器验收。

## 影响范围

| 对象 | 影响 | 兼容策略 |
| --- | --- | --- |
| `ClientCatalogService` | 公开项目列表和详情不再访问基线外的旧 `storeup` 表 | 保留 `storeupnum` 响应字段并返回当前未启用收藏统计值 0，不改变响应结构 |
| `ClientAuthService` | 注册增加中国大陆 11 位手机号格式校验 | 校验发生在任何数据库访问和写入之前；合法号码的原事务流程不变 |
| Docker 反向代理 | 保留外层 HTTPS 协议与主机，后端识别同源请求 | 不开放通配 CORS；本地端口白名单保持不变 |
| 客户端 API | 统一解析后端中文错误和网络错误 | 不显示 Axios 英文状态码，不暴露服务器异常细节 |
| 客户端首页 | 项目、技师和轮播分别处理成功或失败 | 一个公开接口失败不再清空其他已成功模块 |

## 数据库、接口与权限

- 不新增、不修改、不删除数据库表、索引、约束或历史数据。
- Flyway 最新版本保持 `2026080103`，不新增迁移脚本。
- 公开项目、技师和注册接口的路径、方法、权限与响应外形不变。
- 不修改预约、支付、套餐、库存、退款、提成状态机或权限模型。
- `storeup` 不属于 V1.3 当前数据库基线，因此不为修复查询而伪造兼容表。

## 回滚方案

1. 回滚后端和前端镜像到 M6-10 已验收版本。
2. 恢复两端 Nginx 配置和 Spring 转发头配置。
3. 无数据库变更，不执行数据库回滚，不修改 `flyway_schema_history`。
4. 若仅代理配置回滚，临时公网 HTTPS 会再次触发 403；本地同源端口仍可使用。

## 安全说明

- 未将 `allowedOrigins` 设置为 `*`，也未允许任意公网来源携带凭据。
- Docker 后端端口仍只绑定 `127.0.0.1`，可信转发头由同机反向代理提供。
- 测试数据使用虚构姓名和号码；本次公网验证未写入有效会员测试记录。
