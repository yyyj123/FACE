# M6-01 至 M6-05 经营分析接口与口径

## 1. 基线对应关系

- PRD V1.1：归属 M6 经营分析，只交付有可靠交易事实支撑的 P0 指标。
- 数据库 V1.1：基于 `sales_order`、`sales_order_item`，增加成交维度快照，不跨模块直接读取其他模块私有表。
- API V1.1：新增商业能力使用 `/api/v3`。
- 分阶段实施与验收 V1.1：测试、迁移、权限、错误处理、文档和构建均纳入 M6-01 验收。

本任务不声称已经实现套餐核销、库存成本、提成结算、利润率或外部市场占有率。

## 2. 接口

### `GET /api/v3/analytics/sales/overview`

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `shopId` | 否 | 必须位于当前账号授权门店范围 |
| `fromDate` | 否 | 默认最近 30 天 |
| `toDate` | 否 | 默认当天 |
| `itemType` | 否 | `ALL`、`SERVICE`、`PRODUCT` |

日期范围最多 93 个自然日。订单级指标始终按门店和日期范围内的全部有效订单计算；
`itemType` 只影响品项排行、品类构成和销售明细。

响应包含：

- `summary`：订单数、消费会员数、订单原价、折扣、实收、退款和净收款。
- `comparison`：与当前周期等长、紧邻的上一周期订单级汇总。
- `shopBreakdown`：按当前账号授权门店汇总订单、客户、实收、退款和净收款。
- `itemTypeBreakdown`：服务项目与零售商品的退款前订单行成交额。
- `ranking`：按退款前订单行成交额排序的品项。
- `categoryComposition`：门店内部品类销售结构。
- `brandComposition`：零售商品品牌销售结构，未标注品牌独立列示。
- `trend`：订单级实收、退款和净收款日趋势。
- `dataQuality`：指标版本、退款分摊限制和维度快照质量说明。

### `GET /api/v3/analytics/sales/lines`

除公共筛选参数外，支持 `page`、`pageSize`。响应不返回会员姓名、手机号、证件、
健康资料或支付凭据。订单退款仅作为订单级字段展示，不伪造到单个订单行。

## 3. 权限与模块边界

- 两个接口都要求 `analytics:view`。
- 后端使用当前身份的租户和授权门店作为强制数据范围。
- 经营分析控制器通过 `TransactionAnalyticsQueryPort` 调用交易模块应用服务。
- 交易模块内部负责查询订单私有表；分析模块不直接访问交易模块私有表。
- `/api/v2/context` 以兼容方式增加 `permissions`，用于前端菜单和路由提示；后端仍是最终授权边界。

## 4. 指标定义

| 指标 | 定义 |
|---|---|
| 有效订单 | 状态为已支付或退款的订单 |
| 消费客户 | 有效订单中非空会员 ID 去重 |
| 实收金额 | 有效订单 `collected_amount` 汇总 |
| 退款金额 | 有效订单 `refunded_amount` 汇总 |
| 净收款 | 实收金额减退款金额 |
| 品项成交额 | 订单行 `line_amount` 汇总，退款前口径 |
| 品类占有 | 仅表示所选门店内部销售构成，不代表外部市场份额 |
| 品牌销售构成 | 仅汇总零售商品退款前订单行成交额，不代表外部品牌市场份额 |

当前 `metricVersion` 为 `M6-04-v1`，`refundAllocation` 为
`ORDER_LEVEL_ONLY`。在建立可靠退款明细与冲正关联前，不允许提供虚假的行级退款或利润。

M6-02 复用 M6-01 已建立的 `brand_name_snapshot`，没有新增表结构。服务项目不参与品牌构成；
当筛选范围为 `SERVICE` 时返回空的 `brandComposition`，而不是把项目名称误作品牌。

M6-03 增加 `shopBreakdown`。交易模块只按订单表中的 `shop_id` 分组，不跨模块读取门店私有表；
管理端使用已经授权的门店上下文映射门店名称。指定 `shopId` 时只返回单店结果，清空门店筛选后
才比较全部授权门店。门店对比不受品项类型筛选影响，避免把混合订单的订单级实收错误拆给品项。

M6-04 增加 `comparison`。上一周期的自然日数量与当前周期完全相同，结束日期为当前开始日期的
前一天；两个周期复用同一租户、门店权限和有效订单状态。上一周期为零时不计算无限增长率，
管理端显示“无基期”。对比仍是订单级口径，不受品项类型筛选影响。

M6-05 不改变上述指标，新增 `report_snapshot` 固化 overview CSV。快照记录筛选条件、授权门店、
`metricVersion`、请求/内容 SHA-256、字节数、行数和 30 天期限。文本单元格会中和公式前缀；
CSV 不包含销售明细中的订单号，也不包含任何会员、健康、支付或密码字段。

## 5. 错误与审计

- 无权限：HTTP 403。
- 门店越权：HTTP 403。
- 日期倒置、范围超过 93 天或非法品项类型：业务参数错误。
- 查询和报表都不改变订单、退款、库存或提成状态。
- `analytics:export` 已由 M6-05 开放给受授权账号；创建和下载均写审计，下载前重新校验当前门店权限。
- 报表列表、详情和下载强制创建账号本人范围；过期返回 HTTP 410。
