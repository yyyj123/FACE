# 项目发布前内容清理计划

## 目标

在不删除图片资产、不恢复已暂停范围、不改变当前可见产品边界的前提下，清理仓库中的遗留实验实现、非业务文档、临时命名和测试标记，并为后续 GitHub 发布形成可审计的项目快照。

## 变更范围

1. 删除旧后端中未被当前主线使用的第三方识别、翻译和图像分析工具及其依赖。
2. 移除硬编码的第三方访问凭据，并确保发布历史不再包含这些旧对象。
3. 保留服务图片，将图片目录从开发来源命名改为业务目录命名，并同步数据库脚本、测试与说明文档。
4. 删除纯开发过程审阅报告；保留产品规格、阶段计划和验收结论，但使用中性项目术语与目录。
5. 清理测试数据、截图路径、文档标题和文件名中的工具品牌标识。
6. 运行敏感信息扫描、关键字扫描、构建与范围契约验证。
7. 后续发布时以当前清理结果建立单一初始提交，不上传旧提交、标签或暂停中的本地 stash。

## 边界

- 不删除任何图片文件。
- 不恢复或实现微信小程序、SC10、真实渠道或生产切换。
- 不删除历史技师端、复杂多角色后台、采购、提成、培训相关代码或数据表。
- Java 依赖中的技术术语（例如代理库）和 SQL 中的普通别名不属于清理范围。

## 验证

- 检查当前快照不再包含非业务工具品牌、临时过程目录或硬编码第三方凭据。
- 验证所有受影响的静态资源引用均指向存在的图片。
- 执行 SC0 范围契约和受影响模块的测试/构建。
- 检查 Git 状态和待发布对象，确保旧历史不会被推送。
