# 曜石精密座舱：用户端与管理端 UI 重设计规格

## 目标与范围

同时重设计 `C:\project\front` 用户端与 `C:\project\admin` 管理端。保持现有 Vue 2、Element UI、路由、接口、权限和业务数据流不变，只调整视觉系统、页面结构表达、组件外观、交互反馈及响应式行为。

用户端服务汽车车主，强调沉浸感、车辆与服务状态、预约和售后路径。管理端服务运营与维修管理人员，强调信息密度、扫描效率和长时间使用舒适度。

## 设计方向

采用“曜石精密座舱”：

- 劳斯莱斯：克制的空间、沉稳材质、安静而明确的层级。
- 法拉利：关键动作的速度感、短促精准的红色信号与动态反馈。
- 布加迪：细密网格、金属线条、精确数字和稀缺感。

不使用车企商标、车型专属造型或受保护品牌资产。设计只提炼气质，不仿制任何品牌官网。

## 视觉系统

### 色彩

- 主背景：近黑曜石色，不使用纯黑，保证层次可辨。
- 一级表面：深石墨；二级表面：略亮枪灰。
- 主文本：冷白；次文本：高对比银灰。
- 主操作：克制的性能红，仅用于主要 CTA、危险状态和关键进度。
- 高级强调：低饱和香槟金，仅用于选中态、精密数据或少量品牌细节。
- 信息状态：成功、警告、错误、信息色分别建立独立且满足 WCAG 2.1 AA 的语义色。

禁止大面积红金并用、霓虹泛滥、装饰性玻璃拟态和无意义渐变文字。

### 字体与数字

采用单一高可读无衬线字体栈，通过字重、字宽和间距形成层级。标题紧凑但不低于 `-0.04em` 字距；正文最小 `1rem`。里程、日期、金额、编号和状态数据启用等宽数字。管理端使用固定 rem 字阶，用户端仅大标题允许受控缩放。

### 空间与形状

使用 4px 基础间距阶梯：4、8、12、16、24、32、48、64。卡片圆角控制在 8–14px；按钮可使用轻微切角或小圆角，不使用夸张胶囊和 24px 以上卡片圆角。边框采用细金属线，阴影短而克制。

## 共享组件系统

在两端分别建立同语义、适应各自代码结构的主题层：

- 按钮：主操作、次操作、幽灵、危险、图标按钮，覆盖默认、悬停、焦点、按下、禁用和加载状态。
- 输入：输入框、选择器、日期、上传、搜索，统一高度、描边、焦点环、错误和禁用状态。
- 导航：顶部导航、侧栏、面包屑、标签页和移动端菜单。
- 数据：列表、卡片、表格、状态徽标、分页、空状态和骨架加载。
- 反馈：弹窗、抽屉、通知、确认、错误提示与加载遮罩。

Uiverse 只作为交互细节参考，选择微光描边、精密按钮、输入焦点和加载反馈等适配元素，按项目令牌重写 HTML/CSS。避免直接拼贴互不一致的社区组件。使用前记录参考链接和 MIT 许可来源。

## 用户端结构

### 全局框架

重构首页外壳的顶部品牌区、主导航、账户入口、轮播/主视觉和页脚。导航在桌面保持轻薄悬浮层，在移动端折叠为可键盘操作的菜单。当前路由以香槟金细线或性能红短标识明确显示。

### 首页

首屏以车辆和服务为核心，不采用通用指标卡模板。大幅图像区承载车型或服务内容，旁侧呈现简洁说明与主要操作。下方按“车辆信息—预约服务—维修进度—售后资料”形成有节奏的非对称布局，避免重复卡片网格。

### 列表、详情与表单

列表强调内容标题、状态和时间，筛选区紧凑且可折叠。详情页将关键信息、媒体和行动区分层。预约及反馈表单按任务顺序分组，错误信息紧邻字段，提交状态明确。

### 登录、注册与个人中心

采用深色双区构图：品牌氛围区与清晰表单区。个人中心围绕车辆、预约、维修和售后记录组织，不使用装饰性统计。

## 管理端结构

### 应用外壳

侧栏保持熟悉的信息架构，改为深石墨分层；顶部工具栏承载页面标题、账户和关键操作。选中项使用细金线与轻微表面提升，不用大面积高饱和背景。

### 表格与筛选

表格为主要工作表面：固定表头、清晰行高、稳定列对齐、等宽数字、可辨识悬停与选中状态。筛选和批量操作位于表格上方同一工具带；危险操作不与常规操作等权。

### 表单与详情

复杂表单采用分区标题与自然阅读顺序。详情优先展示状态、对象标识和最近活动。弹窗只用于短任务；较长编辑流程保留页面或抽屉形式。

## 动效与交互

- 常规状态过渡为 150–250ms，使用平滑减速曲线。
- 主按钮允许一次轻微扫光或边缘亮度变化，禁止循环发光。
- 页面内容默认可见；进入动画不阻塞阅读和操作。
- 表格、菜单和表单动效只表达状态变化。
- `prefers-reduced-motion: reduce` 下关闭位移和扫光，保留即时颜色反馈。
- 所有可交互元素具备可见的 `:focus-visible`，触控目标至少 44×44px。

## 响应式策略

用户端覆盖 360px、768px、1280px 与宽屏。首页结构在移动端重新编排，不只是整体缩小。管理端在窄屏折叠侧栏、允许表格水平滚动，并将高频操作保持可见。正文在 200% 缩放下不丢失内容或功能。

## 技术实现边界

- 保留 Vue 2 和 Element UI，不引入第二套大型组件库。
- 通过 CSS 自定义属性建立主题令牌，并集中覆盖 Element UI。
- 优先改造共享外壳与全局组件，再处理页面局部样式。
- 不修改接口字段、路由名称、权限判断和业务方法。
- 全部用户可见图片重新选型，包括首页轮播/主视觉、车辆、维修服务、售后资料、内容缩略图、登录注册背景和空状态媒体。
- 管理端仅替换品牌氛围图与真实业务内容缩略图，不在表格、筛选和数据工作台中加入无意义装饰图片。
- 图片方向统一为高端汽车摄影、精密机械细节、深色工作室光线和克制材质；避免直接使用劳斯莱斯、法拉利或布加迪的商标、官网素材与无法确认授权的品牌图。
- 每张新增图片必须核验可用来源与许可、原始尺寸、主体安全裁切区和移动端表现；下载为本地资产并按用途压缩，页面不依赖第三方热链。
- 为响应式图片提供合适尺寸或裁切版本；非首屏图片延迟加载，所有有信息意义的图片提供准确替代文本，纯装饰图使用空替代文本。
- 后端位于 `D:\.AAApersonal\biye\bishe\daima\car`，MySQL 数据库为 `127.0.0.1:3307/car`，上传资源位于 `src\main\resources\static\upload`。
- 数据库与上传资源迁移必须先生成时间戳备份和旧值到新值映射；迁移脚本必须支持 dry-run、执行后引用完整性检查和依据映射回滚。
- 替换数据库中的轮播、车辆、服务、故障排查、配件、评价、维修记录、维修资料及示例账户头像图片；保留聊天中由真实用户上传的内容，除非其文件属于初始演示数据。

## 验证与验收

- 两个项目的生产构建均成功。
- 用户端与管理端在桌面、平板和手机关键视口完成浏览器截图检查。
- 登录、导航、搜索、分页、表单提交、弹窗、列表详情跳转和退出登录不因重设计失效。
- 文本和控件满足 WCAG 2.1 AA 对比度；键盘路径、焦点状态和减少动态效果可用。
- 无横向意外溢出、文本截断、遮挡、不可读状态或控制台新增错误。
- 两端共享同一品牌语言，同时保持用户端沉浸、管理端高效的差异。
