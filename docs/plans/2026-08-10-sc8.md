# SC8 双端 DEMO 与客户验收实施计划

日期：2026-08-10  
阶段：SC8  
产品基线：`docs/specs/FACE_用户端与运营管理平台增量升级PRD_V3.0.md` 方案一

## 目标与边界

本阶段只交付 V3.0 双端 DEMO：Compose 网络内统一 Nginx 入口、Cloudflare Quick Tunnel、12 小时演示门禁、固定演示账号、DEMO 短信/支付、完整合成种子数据，以及一键启动、停止、备份和重置。公开入口只包含 `/`、`/admin/`、`/client/`、`/api/`，不得暴露独立技师端。

不进入 SC9；不实现 Linux 生产部署、正式 TLS/域名、生产 Secret、对象存储、监控告警或真实支付/短信/物流适配器。不得使用真实客户数据或真实渠道密钥。

## 实施任务

1. 先补失败契约：验证 demo Compose、内部 Nginx、Quick Tunnel 网络目标、门禁 Cookie 属性、公开路径白名单、显式宿主机端口和四个运维脚本；确认当前仓库失败。
2. 新增 `docker-compose.demo.yml` 与 `demo/` 网关资源。网关仅在 Compose `application` 网络反代 `admin`、`client`、`backend`；`cloudflared` 只访问 `http://gateway:8080`，不使用宿主机端口。
3. 在 `backend-next` 增加仅 `demo` Profile 可用的演示访问会话接口与验证端点。访问密码和签名 Secret 从环境变量注入，使用恒定时间比较和带到期时间的签名 Cookie；Cookie 固定为 12 小时并包含 `HttpOnly; Secure; SameSite=Lax`。
4. 将 admin/client 以 `/admin/`、`/client/` 基路径构建并由网关提供；API 经 `/api/` 转发到统一后端。演示首页只呈现两端入口、API 状态、固定账号说明和 DEMO 安全声明。
5. 新增幂等 DEMO 种子脚本，恢复固定 `SUPER_ADMIN`、`ADMIN`、会员、项目、排班、预约、卡项、积分、商城、发货、评价和售后合成数据；统一演示密码仅通过环境变量输入，禁止写入日志或证据。
6. 新增 `scripts/demo-start.ps1`、`scripts/demo-stop.ps1`、`scripts/demo-backup.ps1`、`scripts/demo-reset.ps1`。启动前显式检查所需端口；停止后同时移除 Quick Tunnel；备份输出到忽略目录；重置只操作显式校验过的 demo Compose 项目并恢复迁移与固定数据。
7. 新增 `scripts/verify-sc8-runtime.ps1` 和浏览器/接口验收脚本，连续两次从干净状态执行 Flyway `migrate`、`validate`、迁移目录与 `flyway_schema_history` 动态比对、后端测试、双前端构建、容器健康、桌面与手机视口主链路、备份、重置、重启、Quick Tunnel 公开访问和停止失效检查。
8. 在 `docs/verification/SC8/` 留存命令、版本、候选 SHA、tag、两轮日志、桌面/手机截图、Quick Tunnel 停止证据、风险和来源限制；更新 `README.md`、`PRODUCT.md`、`CONTRIBUTING.md` 与环境变量示例。

## 验收与停止条件

- 桌面和手机视口经实际 Quick Tunnel URL 完整验证注册、预约、卡项、积分、商城、发货、评价和售后。
- 门禁未授权时不泄露双端或 API；授权 Cookie 属性和 12 小时有效期符合契约。
- DEMO 固定验证码为 `888888`、模拟支付开启；非 demo Profile 不允许固定验证码或模拟支付降级。
- 重置后固定数据指纹恢复；停止后原 Quick Tunnel URL 在限定重试内不可访问。
- 两轮均通过后提交 SC8 候选、生成证据提交并创建 `sc8/v1.0.0` 标签，随后立即停止，等待人工回复“通过，进入 SC9”。
