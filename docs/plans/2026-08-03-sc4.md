# SC4 订单、支付、卡项与护理优惠实施计划

基线：`sc3/v1.0.0`（`005dc1ac2eb65013bd3acca2406704559d520ac0`）
产品来源：`docs/specs/FACE_用户端与运营管理平台增量升级PRD_V3.0.md` 第 7.3、8、9、10、16 节
阶段边界：只执行 SC4；不实现 SC5 的积分批次、积分抵扣、商城、SKU、购物车、拆单、库存冻结与物流。

## 目标与验收口径

- 打通单次护理项目的“时间锁 → 报价 → 用户明确选择优惠 → 创建订单 → 支付/零元成单 → 确认预约”闭环。
- 统一支付适配器支持 `DEMO_MOCK`；微信、支付宝和聚合支付仅保留可配置能力，生产未配置时明确不可用，绝不回退到模拟支付。
- 三类卡项统一复用 `package_product/package_instance` 主线：次卡 `COMBO_TIMES`、储值卡 `STORED_VALUE`、折扣卡 `DISCOUNT`。
- 支持卡项来源 `ONLINE_PURCHASE/OFFLINE_SALE/GIFT/REISSUE`；`LEGACY_IMPORT` 留到 SC7。
- 支持满减券、代金券、折扣券、项目体验券及领取、锁定、使用、释放、过期、作废的追加流水。
- 报价展示活动、优惠券、折扣卡、无优惠；积分明确标记为 SC5 暂不可用。默认不选择优惠，不自动套用所谓最优方案。
- 重复支付回调不得重复确认预约、发卡、使用优惠或写入权益流水；零元订单仍创建 `ZERO_AMOUNT` 成功支付事实。

## 已确认复用边界

- 订单唯一主线继续使用 `sales_order/sales_order_item` 和 `TransactionService`，不新建平行订单主表。
- 支付继续使用 `payment_transaction/payment_callback_event`、`PaymentChannelAdapter`、`PaymentAdapterRegistry` 与现有退款主线。
- 卡项唯一主线继续使用 `package_product/package_instance/package_instance_item/package_ledger`；储值本金/赠送金以挂在卡实例下的批次与追加流水表达。
- 预约和时间锁继续由 SC3 的预约应用服务拥有；SC4 通过明确端口完成锁转换、支付超时释放和预约确认。
- 现有营销投放不是价格活动；护理优惠活动与优惠券使用独立事实表，不复用投放状态机。

## 迁移与数据模型

先增加失败的迁移契约测试，再追加 `backend-next/src/main/resources/db/migration/V2026080304__sc4_order_cards_coupon_benefits.sql`：

- 扩展卡产品/实例的卡类型、来源、适用范围、有效期与折扣规则；既有套餐回填为 `COMBO_TIMES`。
- 次卡继续使用 instance item 与 ledger；增加预约级权益 reservation，状态为 `RESERVED/CONSUMED/RELEASED/REVERSAL`。
- 新增储值本金/赠送金批次、储值流水和冻结明细，所有余额由追加事实汇总，快照只作投影。
- 新增优惠券模板、会员券和优惠券流水，支持 `AVAILABLE/LOCKED/USED/EXPIRED/CANCELLED/RETURNED`。
- 新增价格活动、订单优惠决策快照、权益冻结关联和支付履约记录。
- 调整支付约束以允许金额为零的 `ZERO_AMOUNT` 成功流水，同时保留历史正金额支付约束语义。
- 仅为 `ADMIN/SUPER_ADMIN` 映射本阶段订单、卡项、优惠券与支付配置权限；不恢复历史多岗位可见入口。

SC1 文件计划曾预留 `V2026080303` 给 SC4，但实际 SC3 已使用该版本；本阶段只顺延到 `V2026080304`，不编辑任何既有 Flyway 文件或 history。

## 后端实现顺序

1. 以单元/集成测试锁定金额精度、优惠互斥、默认无优惠、卡券适用规则、冻结/释放/核销和 callback 幂等。
2. 引入权益端口和 `CheckoutApplicationService`，由其拥有结算事务；控制器不直接跨域写表。
3. 将订单创建拆出可复用的服务端定价入口，允许合法零元订单，保存价格和规则快照。
4. 实现 `PaymentCompletionApplicationService`，统一处理同步收款、零元和异步回调成功后的单次履约。
5. 将模拟支付通道命名并隔离为 `DEMO_MOCK`；仅 demo 配置启用。真实通道未配置返回明确不可用，且不改变订单、支付、预约或权益状态。
6. 实现卡产品、发放、储值批次/流水、折扣规则、次卡/储值冻结与释放；完成服务时的最终核销编排仍归 SC6，本阶段只提供受测命令端口，不扩展 SC6 UI。
7. 实现优惠券模板、发券、领取/锁定/使用/释放与退款成功后的可配置返还端口。
8. 所有关键写操作要求 `Idempotency-Key`，更新要求 version/If-Match，资金与权益变更写审计和 outbox。

## 前端实施

用户端：

- 将 `BookingView.vue` 的“确认预约”调整为进入结算；展示项目、技师、时间、条款、优惠候选、支付方式和服务端最终金额。
- 新增结算结果/订单状态交互；零元订单直接完成，待支付订单显示通道状态与安全重试提示。
- 扩展 `BenefitsView.vue` 展示次卡、储值卡、折扣卡、优惠券及可用/冻结/已用状态。
- 补齐 390px 与 1440px 布局、加载/空/错误/过期/重复提交状态和键盘可访问性。

运营管理平台：

- 新增收口后的“卡项与优惠”入口，管理三类卡产品、线下销售、赠送、补发、券模板和发券。
- 扩展交易/对账页面显示 `ZERO_AMOUNT`、支付通道、回调/履约幂等结果和来源。
- 设置页只显示掩码配置状态与启停；不得回显密钥，不得通过前端隐藏代替服务端权限。
- 沿用现有系统字体、白/浅灰表面和玫瑰铜强调色；不新增独立技师端或复杂岗位菜单。
