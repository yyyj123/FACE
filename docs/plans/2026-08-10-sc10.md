# SC10 微信小程序实施计划

日期：2026-08-10
阶段：SC10
产品基线：`docs/specs/FACE_用户端与运营管理平台增量升级PRD_V3.0.md` 方案一
上一阶段基线：`sc9/v1.0.0` / `f9a2a7316192fbda6a73ef801ba86f48080633ed`

## 目标与边界

本阶段只交付复用统一后端的微信小程序：微信身份绑定、面向会员的小程序页面、受控图片上传、微信分享、微信支付预支付参数与回调适配、订阅消息授权与发送适配。

小程序是新的交互壳层，不复制或改写预约、结算、订单、资产、积分、商城、评价、售后、通知的业务状态机。相同手机号必须解析到现有 `MEMBER` 账户和 `member_id`，因此 H5 与小程序看到同一会员资产。所有价格、时段、优惠、积分、库存、支付结果、退款、售后和通知事实仍由 `/api/v3/` 后端校验和落账。

不新增总部端、分店端、技师端或复杂多岗位后台；不在小程序中展示独立技师入口；不删除冻结代码或历史表；不使用真实客户数据、生产 AppSecret、商户私钥或真实支付。真实微信渠道缺少配置、证书或授权时必须失败并保持业务事实不变，禁止伪造外部成功。

## 已确认的代码事实与官方契约

1. `IdentityApplicationService` 和 `V3AuthSessionService` 已以租户内手机号解析唯一 `MEMBER` 账户并签发 V3 会话；微信绑定只允许在官方手机号换取成功后调用该可信服务入口。
2. `CheckoutApplicationService`、`MallApplicationService` 和 `PaymentApplicationService` 已统一创建订单/支付记录并处理幂等回调；微信适配只补充 JSAPI 预支付参数、验签解密和标准化回调，不另建支付状态机。
3. `NotificationApplicationService` 已提供站内通知事实；微信订阅消息是附加投递通道，发送失败只记录外部失败，不删除或伪造站内通知。
4. SC9 已部署 S3 兼容 MinIO、Secret/Config Tree 和生产 readiness；SC10 上传复用该对象存储，不使用旧 `backend` 中无鉴权的 `/file/upload`。
5. 小程序身份使用微信官方 `code2Session` 与手机号接口，订阅使用官方订阅消息接口，支付遵循微信支付 API v3 的小程序/JSAPI 下单、`wx.requestPayment` 与回调验签解密契约。来源：
   - `https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html`
   - `https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-info/phone-number/getPhoneNumber.html`
   - `https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/mp-message-management/subscribe-message/sendMessage.html`
   - `https://pay.weixin.qq.com/doc/v3/merchant/4012791856`

## 实施任务

1. 先新增失败契约：`scripts/test-sc10-miniapp-contract.ps1`、`backend-next/src/test/java/com/face/platform/wechat/` 和 `miniapp/test/`，覆盖目录/页面/禁止入口、手机号同会员绑定、跨账号拒绝、上传安全、支付适配、回调幂等、订阅授权与失败不伪造成功；记录预期失败。
2. 新增 Flyway 迁移 `backend-next/src/main/resources/db/migration/V2026081001__sc10_wechat_mini_program.sql`，只追加微信身份绑定、订阅授权/投递、会员媒体对象表及约束/索引；不修改历史迁移 checksum。
3. 在 `backend-next/src/main/java/com/face/platform/wechat/` 增加微信平台端口和应用服务：
   - 以 `login_code` 换取 `openid/session_key`，以一次性 `phone_code` 取得手机号；
   - 将 `app_id + openid` 幂等绑定到该手机号已有的 `account_id/member_id`，阻止同一微信身份跨会员重绑；
   - 使用现有 V3 会话签发、租户主体和权限规则；
   - 真实 HTTP 适配器只在配置完整时启用，受控验收适配器仅允许 `demo/test`，`prod` 明确拒绝。
4. 增加受鉴权的 `/api/v3/client/media` 图片上传：仅允许会员本人、白名单用途和 JPEG/PNG/WebP，限制大小，计算 SHA-256，生成不可预测对象键，写入 SC9 S3 兼容存储并登记元数据；生产对象存储凭证通过 Docker Secret/Config Tree 注入。
5. 增加微信支付适配：
   - 现有 checkout/mall checkout 继续创建唯一订单和 `PENDING` 支付；
   - `/api/v3/wechat/miniapp/payments/{paymentNo}/prepare` 校验支付属于当前绑定会员后生成 `wx.requestPayment` 参数；
   - 微信回调验签、AES-GCM 解密后标准化进入现有 `PaymentApplicationService` 幂等处理；金额、订单归属和终态规则仍由既有服务校验；
   - 缺失商户配置/证书时返回不可用且不改变支付状态。
6. 增加订阅消息适配：小程序先调用 `wx.requestSubscribeMessage`，后端只登记明确返回的模板授权；投递任务从既有站内通知生成安全摘要，验证绑定和一次性授权后发送，成功/失败/消费状态可追溯，未配置渠道时仅保留站内通知。
7. 新建 `miniapp/` 原生小程序工程及可重复构建：
   - 页面覆盖登录绑定、首页/服务、预约、会员资产、积分商城、订单、通知、评价售后、个人中心；
   - API 客户端统一使用 `/api/v3/`，令牌刷新与 401 退出一致，关键写请求带幂等键；
   - 图片选择/上传、分享、`wx.requestPayment`、`wx.requestSubscribeMessage` 仅调用适配端点；
   - 视觉沿用 H5 的系统字体、浅色表面、深玫瑰主色、8–12px 圆角和清晰焦点/加载/错误状态；不移植桌面画廊，不出现技师入口。
8. 增加 `scripts/verify-sc10-runtime.ps1` 与 `scripts/sc10-runtime-check.mjs`：显式端口预检，从两个独立干净 Compose project 连续运行，动态执行 Flyway `migrate`/`validate` 并核对迁移目录与 `flyway_schema_history`；运行后端全量测试、双 Web 构建、小程序构建、容器健康与重启。
9. 运行 SC10 跨端回归：同一手机号分别通过 H5 SMS 会话和受控小程序微信会话登录，比较 `account_id/member_id`、卡项/账户/积分/预约/通知结果；验证另一微信身份不能重绑或读取资产；验证小程序请求不能绕过库存、金额、预约和售后规则。
10. 更新 `README.md`、`PRODUCT.md`、`CONTRIBUTING.md` 和生产运维说明；在 `docs/verification/SC10/` 留存基线 SHA、版本、命令、失败测试、两轮完整日志、迁移/身份/支付/订阅/上传/跨端一致性证据、风险和来源限制。证据提交后创建 `sc10/v1.0.0` 标签并立即停止。

## 测试优先顺序

1. 执行 `scripts/test-sc10-miniapp-contract.ps1`，确认小程序工程、迁移、后端适配器、生产 Secret 和验收脚本缺失而失败。
2. 为身份绑定、支付回调规范化、上传策略、订阅授权消费和生产禁用受控适配器分别先写 Java/Node 失败测试，再做最小实现。
3. 运行后端定向测试、小程序 Node 测试与静态契约，随后运行 Maven 全量测试和三端构建。
4. 连续两次运行正式 SC10 验收；任何代码、Compose 或脚本修正后，两轮均从 Run 1 重新开始。

## 验收与停止条件

- 同一手机号的 H5 与小程序会话返回同一 `account_id/member_id/shop_id`，资产、积分、预约、订单和通知查询结果一致。
- `app_id + openid` 唯一且不可跨会员重绑；所有小程序私有接口仍经 V3 Bearer 会话、租户和会员权限校验。
- 小程序页面、分享、上传、支付和订阅消息调用链可构建、可回归；没有独立技师入口或复制业务规则。
- 上传只接受受控图片并写入对象存储；路径不可预测，元数据可追溯，跨账号不可访问/冒用。
- 微信预支付只针对当前会员的待支付记录；回调验签/解密、金额匹配和幂等通过；缺配置时保持 `PENDING`，不伪造成功。
- 订阅授权可追溯且一次性消费；未授权、渠道未配置或发送失败时站内通知仍存在，外部状态不标为成功。
- 两轮均完成后端测试、三端构建、Flyway 动态一致性、容器健康、重启和核心跨端回归；证据无真实客户数据或生产密钥。
- 证据提交并创建 `sc10/v1.0.0` 后立即停止；SC10 是当前 V3.0 路线的最后阶段，不自行开启新增范围。
