# M4 支付适配与对账生命周期

## 1. 模块边界

- `transaction` 负责订单、支付交易与退款业务状态，不直接实现任何通道协议。
- `payment` 负责支付通道适配、回调验签、回调防重放和通道结果归一化。
- `reconciliation` 只读系统支付/退款汇总并保存对账证据，不直接修改订单、支付、退款、会员账户、套餐或库存流水。
- 需要纠正业务账时，必须回到退款、冲正或库存调整应用服务，不能通过对账表直接“抹平”。

## 2. 支付生命周期

### 本地支付

`CASH`、`BALANCE` 继续由交易应用服务在本地事务中执行。余额支付通过会员账户应用服务追加不可变流水。

### 外部支付

1. `POST /api/v3/orders/{orderId}/payments` 创建 `PENDING` 支付并调用适配器。
2. 通道未配置时返回 HTTP 503 `DEPENDENCY_UNAVAILABLE`，不得把支付标记为成功。
3. 当前仅启用 `SANDBOX` 隔离适配器，用于自动化验收；微信、支付宝、银行卡仍保持未配置保护。
4. 通道回调先验签，再按 `(channel_code, channel_event_id)` 防重放。
5. 首次有效成功回调在单一数据库事务内更新支付、订单和回调事件；重复回调返回原处理结果，不重复入账。

## 3. 回调安全

- 请求头：`X-Payment-Timestamp`、`X-Payment-Nonce`、`X-Payment-Signature`。
- 签名材料固定为：时间戳、nonce、原始请求体，使用 HMAC-SHA256。
- 时间戳超过允许偏差、签名不一致、事件编号重复或订单/金额不一致时拒绝处理。
- 数据库只保存业务所需摘要、事件编号、验签结果和处理结果，不保存通道密钥或原始支付凭据。
- 回调入口是唯一匿名 V3 支付入口；其余支付和对账接口仍要求租户令牌与门店权限。

## 4. 退款

- `CASH`、`BALANCE` 使用本地冲正能力。
- 外部支付退款必须委托原支付通道适配器。
- 通道未配置或调用失败时，退款保持 `APPROVED`，不写成功退款交易，不修改订单已退金额。
- 通道返回成功后，保存外部退款编号并继续既有审计、outbox 和汇总更新。

## 5. 对账状态机

`PENDING → RUNNING → MATCHED | DIFFERENT → RESOLVED → CLOSED`

- `MATCHED` 可直接关闭。
- `DIFFERENT` 必须至少追加一条处理记录后进入 `RESOLVED`，再由具备管理权限的账号关闭。
- `CLOSED` 为终态；所有差异项、处理记录和版本信息永久保留。
- `version` 用于防止并发处理和重复关账。

## 6. 权限

- `reconciliation:view`：查看批次、系统汇总、通道汇总、差异项和处理记录。
- `reconciliation:manage`：执行对账、追加处理记录、关闭批次。
- 管理端路由和按钮做前端提示性控制，服务端仍以租户、门店、角色和权限为最终判定。

## 7. 生产接入前置条件

每个真实通道必须另行提供生产适配器、证书/密钥托管、签名算法、回调地址白名单、主动查询、退款查询、超时重试和通道对账文件解析。未满足这些条件时必须保持 `DEPENDENCY_UNAVAILABLE`，不得复用 SANDBOX 密钥或伪造成功。
