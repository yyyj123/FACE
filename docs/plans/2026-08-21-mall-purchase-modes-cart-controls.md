# FACE 商城购买方式展示与购物车控制增量方案

日期：2026-08-21

## 现状扫描

- 商品列表、商品卡片和购物车统一位于 `front-next/src/views/PointsStoreView.vue`。
- 当前没有独立商品详情页或商品卡片组件；不得新建第二套商城页面。
- SKU 由 `/api/v3/client/mall` 返回，价格字段为 `cashPrice`、`pointsPrice`、`comboCashPrice`、`comboPointsPrice`。
- 购买方式开关为 `cashEnabled`、`pointsEnabled`、`comboEnabled`，接口实际模式为 `CASH`、`POINTS`、`COMBINATION`。
- 人民币展示复用 `front-next/src/utils/format.ts` 的 `money()`。
- 购物车读取与覆盖数量已存在；现有接口缺少删除购物车项能力。
- 现有响应式断点为 760px，WEB-R 壳层在 900px 以下使用移动导航。

## 增量设计

1. 提取纯函数商城展示模型：只按后端 SKU 开关与已返回价格生成有效购买方式。
2. 商品卡片隐藏 SKU 编码和三套平铺价格，只显示一个主价格；两种以上购买方式显示动态数量入口。
3. PC 通过悬停或点击入口查看轻量 Popover；移动端点击查看并可关闭。
4. 在现有商城视图内增加商品详情弹层，不新增路由或第二套商城页面。
5. 详情弹层支持 SKU 选择、购买方式选择和动态主按钮；SKU 切换时保留仍有效的方式，否则回落到新 SKU 第一个有效方式。
6. 购物车增加按商品名/规格搜索、数量增加、数量减少和删除；数量覆盖继续复用现有接口。
7. 后端只增加按归属删除购物车项的端点，不调整结算、价格、优惠、库存或订单逻辑。

## 验证

- 纯函数测试覆盖现金、积分、组合、双模式、三模式、无效价格、无可用模式、SKU 切换失效和按钮文案。
- UI 契约测试覆盖列表不展示 SKU 编码、动态购买方式、详情选择、购物车搜索/增减/删除和响应式弹层。
- 后端 API 契约测试覆盖删除端点的会员归属边界。
- 执行前端全量测试与生产构建、后端相关测试，以及 PC/手机四视口浏览器回归。

## 边界

- 不修改订单最终计价、积分扣减、优惠、库存冻结和结算拆单规则。
- 不新增前端依赖，不写死购买方式数量，不在前端推导运营规则。
- 无有效购买方式时显示“暂不可购买”，不得显示零价、空值或非法数字。
