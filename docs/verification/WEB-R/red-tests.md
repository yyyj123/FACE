# WEB-R RED 与迭代记录

## 初始 RED

在修改实现前新增并运行 WEB-R 静态契约与双端源码契约。首次静态验证以非零状态退出，16 项预期缺失被捕获，集中在：用户端同步路由导入、两端缺少跳过导航和路由焦点恢复、运营端抽屉缺少 ARIA/Escape/焦点归还/背景锁定、移动安全区与 44px 目标缺失、加载状态未统一暴露给辅助技术，以及公开用户壳层仍存在技师模式导航分支。

实现后同一契约转为 `WEB_R_UI_STATIC_CONTRACT=PASS`，用户端测试 9/9、运营端测试 3/3。

## 验收器迭代

1. 初始浏览器登录流程依赖页面表单，受门禁和异步时序影响；改为通过真实门禁/API 获取会话，再按应用实际 localStorage 格式注入，仍完整经过统一后端认证契约。
2. Cloudflare Quick Tunnel 在密集矩阵中出现临时网络抖动；矩阵改用同一 Compose 网关的显式本机端口，SC8 回归继续验证公网门禁、Secure/HttpOnly Cookie、隧道启动和停止失效。
3. 企业托管 Edge 扩展产生与 FACE 无关的 `chrome-extension://pdff...` 消息端口异常；验收器仅按扩展 URL 来源隔离计数，FACE 运行时异常、本站 5xx、加载失败仍保持严格失败。
4. PowerShell 5.1 对脚本源码中的中文默认截图路径发生代码页误解；最终脚本改用仓库内的纯英文预览路径，避免代码页差异。
5. 每次运行代码或验收脚本修正后均废弃此前诊断轮次。最后一次路径修正后从 Run 1 重新开始，随后在不改代码的条件下连续完成 Run 2；只有 `run-1`、`run-2`、`run-11`、`run-12` 是正式结论来源。

诊断截图 `run-23`/`run-24` 仅保留在外部预览目录供追溯，不属于正式验收矩阵。
