- 当前任务：M3-01 基线复核、差距识别、影响分析和迁移设计

## 2. M3 验收口径

1. 预约只能按合法状态机流转；通用状态接口不得直接写入 `COMPLETED`。
2. 护理完成必须在同一事务内完成护理事实、耗材明细、库存扣减、库存流水、预约完成、审计日志和完成事件。
3. 任一写入失败时，上述事务全部回滚；库存不得为负。
4. 已完成护理事实不可覆盖，只能追加有原因、有操作者、有时间的更正记录。
5. 顾客确认独立于预约和护理状态，仅本人可确认或拒绝，并保留审计。
6. 单次订单创建和收款可安全重试；相同幂等键同请求返回相同结果，不同请求冲突。
7. 店长/前台、技师、会员分别能完成其权限范围内的操作，后端权限不能只依赖菜单隐藏。
8. 三端真实业务走查、API 契约、MySQL 8 Flyway、构建、自动化测试、日志脱敏全部通过。

## 3. 现状与差距

| 范围 | 当前实现 | M3 基线要求 | 处理 |
|---|---|---|---|
| 预约状态 | 已有合法流转校验，通用完成已阻止 | 完成只能由护理完成应用服务触发 | 保留规则，抽出预约生命周期应用服务 |
| 跨模块边界 | 护理服务直接更新预约表和历史表 | 模块不得直接写其他模块私有表 | 由预约模块提供开始/完成协作服务 |
| 护理完成 | 已有事务、护理明细、耗材和库存扣减 | 同事务还需预约、审计、outbox、顾客待确认 | 补齐事务内事件和确认记录，并做失败注入 |
| 已完成护理 | 当前“编辑护理”会覆盖已完成事实 | 已完成事实不可变，只能追加更正/作废 | 禁止覆盖，新增追加式更正 |
| 顾客确认 | 未实现 | 独立状态 `PENDING/CONFIRMED/REJECTED` | 新表、新服务、会员本人接口与页面 |
| 订单创建 | 预约唯一约束可防重复，但无完整请求幂等 | 关键写必须使用幂等键并校验请求摘要 | 增加订单创建幂等字段/索引和稳定重放 |
| 支付 | 已有支付幂等和订单锁 | V3 Header 幂等、稳定响应、审计/事件 | 保留事务逻辑，补 V3 适配和事件验证 |
| 服务完成事件 | 已有 `outbox_event` 表，业务未写入 | 事务内写 `ServiceRecordCompleted` | 新增 outbox 应用服务 |
| 技师端 | 可登录、看预约、改通用状态 | 应有工作台、开工、护理记录、耗材和完成 | 增加专用接口和移动端工作台 |
| 会员端 | 可看/取消预约 | 可查看护理结果并确认/拒绝 | 增加结果与确认入口 |
| 管理端 | 已有护理与交易页面 | 需显示确认、更正、完整审计链 | 改为追加更正并展示状态 |

## 4. 影响模块

### 4.1 后端

- `appointment`
  - 提供预约开始、护理完成的应用服务。
  - 统一拥有预约表、状态历史和资源释放写入。
  - 保留版本校验和行锁。
- `servicecare`
  - 护理开始/完成通过预约应用服务协作。
  - 新增护理更正和顾客确认。
  - 完成事务内调用库存服务、预约服务、审计和 outbox 服务。
- `inventory`
  - 继续通过 `InventoryService` 提供扣减，不允许护理模块直接访问库存私有表。
  - 保持余额与流水同事务、行锁和非负校验。
- `transaction`
  - 增加订单创建幂等和 V3 接口适配。
  - 支付继续锁定订单并保留支付幂等，成功后写审计/事件。
- `security/audit`
  - 新增更正和确认权限。
  - 所有接口按租户、门店、本人或本人预约关系校验。
  - 日志与事件载荷只记录业务 ID，不记录手机号、健康描述或支付凭据。

### 4.2 数据库

- 新增 `customer_confirmation`。
- 新增 `service_record_correction`。
- 为 `sales_order` 增加创建幂等键和请求摘要（扩展式可空字段，历史行兼容）。
- 复用既有 `outbox_event`，不另建重复事件表。
- 新增权限资源及角色授权。

### 4.3 API

- 增加 V3 预约专用动作：确认、签到、开工、取消。
- 增加 V3 护理记录：创建/草稿、完成、追加更正。
- 增加 V3 会员确认和技师工作台。
- 增加 V3 订单创建与支付；关键写统一读取 `Idempotency-Key`。
- 保留 V2 路由作为兼容层，但禁止 V2 覆盖已完成护理事实。

### 4.4 前端

- 管理端：护理完成后的修改改为“追加更正”，展示确认状态和更正历史。
- 技师端：今日工作台、签到后开工、护理记录、耗材、完成确认。
- 会员端：查看护理结果、确认或拒绝并填写原因。
- 延续系统白色主题和现有响应式规范。

## 5. 状态、权限与一致性

### 5.1 状态

- 预约：`PENDING -> CONFIRMED -> CHECKED_IN -> IN_SERVICE -> COMPLETED`
- 预约取消/爽约：按基线允许的来源状态进入 `CANCELLED/NO_SHOW`，必须记录原因。
- 护理：`DRAFT -> IN_PROGRESS -> COMPLETED/VOIDED`
- 顾客确认：`PENDING -> CONFIRMED/REJECTED`
- 顾客确认不会反向修改预约或护理完成状态。

### 5.2 事务边界

护理完成事务必须按以下顺序在一个 Spring 事务内执行：

1. 锁定并校验护理记录和预约版本/状态。
2. 写入护理快照与耗材快照。
3. 调用库存模块扣减余额并写库存流水。
4. 将护理记录置为 `COMPLETED`。
5. 调用预约模块将预约置为 `COMPLETED` 并释放资源。
6. 创建顾客 `PENDING` 确认记录。
7. 写审计日志和 `ServiceRecordCompleted` outbox 事件。

任何一步异常均整体回滚。

### 5.3 权限

- 店主/店长：查看全店、追加更正、交易操作、审计查看。
- 技师：仅操作分配给自己的预约和护理；不得修改他人记录。
- 会员：仅查看和确认与当前账户绑定会员本人相关的护理结果。
- 权限由后端强制，前端菜单和按钮仅做体验控制。

## 6. 迁移、兼容与回滚

### 6.1 迁移策略

- 使用新的 Flyway 版本 `V2026072804`，只做扩展，不删除或重命名现有列。
- 新表先创建，再补索引和外键；订单幂等列先允许 `NULL`，避免影响历史订单。
- 唯一索引仅约束非空新数据；历史订单按原预约唯一约束继续可用。
- 新代码上线后才开始写顾客确认、更正和 outbox 事件。

### 6.2 索引

- 顾客确认：租户/护理记录/类型/会员唯一；会员状态查询索引；门店时间索引。
- 护理更正：租户/护理记录/创建时间索引。
- 订单幂等：租户/创建幂等键唯一。
- 外键和查询索引名称显式、可由迁移验证脚本检查。

### 6.3 兼容

- V2 查询继续返回原字段；新增字段只追加。
- V2 完成接口保留并进入同一领域服务。
- V2 已完成护理编辑接口改为明确冲突响应，防止继续破坏历史事实。
- 历史已完成护理不回填顾客确认；查询时显示“历史记录/无需确认”，避免伪造确认。

### 6.4 回滚

- 应用回滚：旧版本可忽略新增表和可空列。
- 数据库回滚：常规回滚不删除新表，停止新写入并保留数据；若必须物理移除，先导出新增数据并在维护窗口执行单独人工脚本。
- 已产生的顾客确认、更正、outbox 和幂等记录不得通过普通回滚删除。

## 7. 测试先行清单

1. 预约通用状态接口不能完成预约。
2. 技师只能开工/完成自己的预约。
3. 护理完成成功时护理、耗材、库存、预约、确认、审计、outbox 同时落库。
4. 在库存、预约、确认、outbox 各关键点注入失败时全部回滚。
5. 库存不足并发扣减时最多一个成功且余额不为负。
6. 相同护理完成幂等键重试不重复扣库存；不同请求冲突。
7. 已完成护理不能被覆盖；更正只能追加并保留原因/操作者。
8. 会员只能确认自己的记录；重复同请求可重放，不同请求冲突。
9. 订单创建与支付相同键重放稳定，不同负载冲突。
10. 审计和 outbox 不包含手机号、健康详情和支付凭据。
