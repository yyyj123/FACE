# M2 基础资料与服务资源实现契约

## 模块边界

- `masterdata`：项目资料、技师技能版本、排班与主数据查询。
- `resource`：房间/设备资料和预约占用。
- `appointment`：预约状态机；只通过 `ResourceBookingService` 协作，
  不直接写资源模块私有表。
- `idempotency`：V3 写命令的请求哈希、重放和冲突保护。
- `v3/masterdata`：契约适配、权限入口和统一响应，不承载领域规则。

## 关键不变量

1. 所有查询和写入都带 `tenant_id` 与 `shop_id` 范围。
2. 同一技师、项目任一时点最多一个当前技能版本；旧版本只关闭有效期。
3. 排班重叠由应用服务在员工行锁内检查；停用通过状态更新完成。
4. 预约资源按资源编号排序并执行 `FOR UPDATE`，避免反向锁顺序。
5. 重叠的 `RESERVED` 数量小于资源 `capacity` 时才可继续预约。
6. 预约与资源占用在同一事务内提交或回滚。
7. 取消、爽约、完成和改期释放占用时只更新状态，禁止删除历史。
8. 项目、资源、技能、排班写操作必须同时具备权限、幂等和审计。

## 兼容策略

- `staff_skill_version` 是技能事实表；变更时双写旧 `staff_service`，保障
  V1/V2 查询兼容。
- `service_resource` 独立于库存 `ROOM` 库位，防止服务资源与库存地点混用。
- `service_item`、`staff_schedule` 只做扩展字段变更，旧列和旧数据不删除。
- 新接口只挂载在 `/api/v3`；旧响应结构和认证头不改变。

## 冲突与错误

| 场景 | 结果 |
|---|---|
| 资源不存在、跨租户或跨门店 | 404，不泄露其他租户数据 |
| 资源停用 | 409 |
| 重叠占用达到容量 | 409，预约与占用全部回滚 |
| 排班重叠 | 409 |
| 乐观版本不一致 | 409，要求刷新 |
| 相同幂等键、不同负载 | 409 |
| 权限或门店范围不足 | 403 |

## 可观测性

- 领域变更写 `audit_log`，只记录实体、动作和非敏感摘要。
- 隔离验收只输出表行数、状态计数和 PASS/FAIL。
- readiness 将 `staff_skill_version`、`service_resource`、
  `resource_booking` 纳入必需表。
