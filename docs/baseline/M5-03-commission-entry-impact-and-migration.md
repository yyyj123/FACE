# M5-03 提成流水、冻结与退款冲正影响说明

## 1. 任务与验收

- 阶段：M5-03。
- 输入：四份 V1.2 商业基线、M5-01 生命周期/API 契约、M5-02 规则版本与来源快照。
- 输出：自动提成入账、流水查询、冻结/解冻、退款比例冲正、历史重算校验和领域事件投影。
- 验收：服务完成与支付成功无论先后都只入账一次；同一事件可重放；原流水不可覆盖；退款生成负向冲正；技师只能看本人；冻结/解冻有版本、幂等、审计和历史；新鲜库及 M1-M4 历史链通过。

## 2. 影响模块

- 提成：新增流水、状态历史、领域事件投影和规则匹配。
- 服务记录：继续发布 `ServiceRecordCompleted`，不直接写提成私有表。
- 支付：继续发布 `PaymentSucceeded`，不直接写提成私有表。
- 退款：继续发布 `RefundCompleted`，不直接写提成私有表。
- 权限：新增 `commission:freeze`；`commission:entry:view` 保持管理范围/技师 SELF。
- 审计与 outbox：提成入账、冻结、解冻和冲正均追加记录，不包含客户或护理敏感正文。

模块间通过已有 outbox 领域事件和提成投影应用服务协作，不允许服务、支付或退款模块直接访问提成私有表。

## 3. 表结构与索引方案

计划新增：

- `commission_entry`：不可变金额事实、来源快照、规则版本、原流水/退款引用、状态和乐观锁。
- `commission_entry_history`：入账、冻结、解冻、冲正的只追加状态历史。
- `commission_event_projection`：outbox 事件消费检查点、重试次数和安全错误码。

关键约束：

- 稳定 `source_entry_key` 在租户内唯一，防止同来源重复入账和同退款重复冲正。
- 冲正流水必须引用原流水和成功退款；原流水金额不更新。
- 流水金额必须与类型方向一致：入账为正、冲正为负。
- 冻结只允许 `PENDING -> FROZEN`，解冻只允许 `FROZEN -> PENDING`。
- 历史幂等键唯一，状态变更使用 `version` 乐观锁。
- 投影以 `outbox_event.id` 唯一，至少一次扫描、业务唯一键最终幂等。

## 4. 兼容与历史数据

- 采用 Expand 迁移，不修改订单、支付、退款、服务记录、库存、套餐和既有账务表。
- 不回填或猜测迁移前历史提成；仅处理迁移后可验证的领域事件。
- 服务先完成、后支付或先支付、后完成均可触发同一受控入账函数，唯一键保证只生成一次。
- 规则、来源快照和流水共同保存历史事实；重算只比较，不覆盖金额。
- M5-04 结算前仅允许 `PENDING/FROZEN`；已结算冲正在后续批次以负向流水处理。

## 5. 退款迁移与失败策略

- `RefundCompleted` 在退款事务中写入 outbox，提成投影在退款提交后独立处理，避免外部退款已经成功却因提成异常回滚本地退款事实。
- 部分退款按 `退款金额 / 原订单实付金额` 比例冲正，金额按两位小数确定性舍入；累计冲正不得超过原流水。
- 全额或最后一笔退款使用剩余可冲正金额，消除多次舍入尾差。
- 投影失败保存安全错误码并重试；不覆盖原流水，不伪造冲正完成。M5-04 结算将排除存在未完成退款投影的相关流水。

## 6. 回滚方案

1. 停止 M5-03 投影调度和写接口，应用回滚到 M5-02。
2. 三张新表保留只读，不直接 DROP；M5-02 规则和来源快照继续有效。
3. 若已产生提成或冲正，不删除流水；业务纠正必须追加反向流水。
4. 物理结构清理前导出新表、outbox、审计和 Flyway 历史，并确认没有 M5-04 结算引用后由 DBA 单独执行。

## 7. 测试先行清单

1. 迁移契约：表、唯一键、检查约束、权限、无 DROP/DELETE。
2. 状态策略：冻结/解冻合法路径，结算或冲正流水不可非法切换。
3. 退款比例：部分退款、最终尾差、累计上限和零金额拒绝。
4. 事件幂等：支付/完成顺序互换、同事件重放、同来源不同事实冲突。
5. 权限：技师仅本人流水，不能冻结；管理/财务按授权操作。
6. 历史重算：按规则版本和来源快照复算一致，原金额不更新。
7. 事务：投影失败不改变退款成功事实；失败检查点可重试。
