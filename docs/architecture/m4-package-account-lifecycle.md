# M4 套餐与会员账户实现契约

## 模块边界

- `packageaccount` 拥有套餐产品、套餐实例、套餐流水和会员账户应用服务。
- `transaction` 拥有订单与支付状态，只通过套餐目录服务解析套餐订单项，
  通过账户应用服务执行余额支付或退款入账。
- `servicecare` 拥有护理记录，仅提供受权限保护的核销上下文；套餐模块不得直接
  修改护理记录私有表。
- `member` 负责校验会员在租户、门店内有效；套餐与账户服务不复制会员状态规则。
- `outbox` 与业务事实同事务提交；控制器只负责认证、DTO 和稳定响应。

模块边界契约测试禁止交易、护理和控制器直接写套餐或会员账户私有表。

## 套餐生命周期

```text
套餐产品 DRAFT → ACTIVE → INACTIVE
已支付订单 → 发放 ACTIVE 套餐实例
ACTIVE → FROZEN → ACTIVE
ACTIVE/FROZEN → EXPIRED（由有效期判定）
ACTIVE → USED_UP（剩余次数为 0）
```

- 发放必须关联已支付订单和有效套餐产品。
- 同一订单、套餐产品和幂等键只能生成一次实例。
- 套餐内容发放后按快照保存，产品后续变化不改写历史实例。
- 核销必须关联已开始且分配给当前技师的护理记录，并匹配护理项目。
- 核销锁定实例和项目余额，校验状态、有效期、版本与剩余次数。
- 冲正只追加反向流水并恢复余额，不覆盖原核销流水。

## 会员账户规则

- 每名会员具有余额、赠送金、积分三个独立账户。
- 人工入账/扣减要求正数金额、有效流水类型、幂等键、请求摘要和账户版本。
- 余额不足、冻结状态或版本冲突均拒绝写入。
- 冲正锁定原流水和账户，使用账户主键更新余额，并追加
  `reversal_of_ledger_id` 指向原流水。
- 订单余额支付和退款退回通过 `MemberAccountApplicationService`，交易模块不直写
  `member_account` 或 `member_account_ledger`。

## 权限与数据范围

- 管理端：门店范围加 `package:*`、`account:*` 细粒度权限。
- 技师：只可查看、核销分配给本人护理记录对应的套餐，不可查看会员资金余额。
- 会员：仅可查询本人套餐、账户和流水。
- 跨租户、跨门店和缺少 SELF 绑定时返回拒绝，不泄露目标对象是否存在。
- 管理和冲正操作记录审计；流水与 outbox 不保存手机号、健康详情、密码、
  原始令牌或支付凭据。

## 原子性、幂等与版本

套餐发放、核销、冲正和账户变动均在数据库事务中完成：

1. 校验租户、门店、角色和 SELF 范围。
2. 比较幂等键与稳定请求摘要。
3. `FOR UPDATE` 锁定业务对象。
4. 校验状态、有效期、余额和乐观版本。
5. 更新余额快照并追加不可变流水。
6. 写审计和 outbox。

任一步失败整体回滚；同键同载荷返回原结果，同键异载荷和版本冲突返回 409。

## 三端交付

- 管理端 `/assets`：套餐产品、会员套餐、发放、冻结/解冻、账户调账与冲正。
- 技师端 `/appointments`：在护理工作台内按服务记录执行套餐核销。
- 会员端 `/benefits`：移动端查询本人套餐、有效期、项目余次、账户和流水。
- 三端沿用白色主题、玫瑰铜强调色和现有响应式布局。

完整端点契约见 `docs/architecture/api-contract-m4.md`。
