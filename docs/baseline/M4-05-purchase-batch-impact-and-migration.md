# M4-05 采购与批次库存影响及迁移方案

## 开工检查

- 当前阶段：M4-05。
- 输入：四份 V1.1 冻结基线、M4 差距矩阵、M4 API 补充契约、M4-04 已验收代码。
- 输出：采购单、审批、部分/全部收货、库存批次、批次流水、权限、API、管理端和验收。
- 验收：幂等收货不重复入库，并发累计不超采购数量；批次合计与地点库存一致；差异、
  越权、版本冲突和故障注入均不留下半成品数据。

## 影响模块

- `purchase`：拥有采购单、明细、收货单和收货明细；不得直接写库存私有表。
- `inventory`：拥有批次、批次流水、地点余额和库存流水；提供受控采购入库应用服务。
- `admin-next`：库存模块增加采购与批次视图；沿用白色主题和门店权限。
- `transaction/servicecare`：不改接口，只需回归现有销售出库和护理耗材扣减。
- 权限：新增 `purchase:view`、`purchase:manage`、`purchase:approve`、
  `purchase:receive`；库存查询继续使用 `inventory:view`。

## 状态和事务

```text
DRAFT -> SUBMITTED -> APPROVED -> PARTIALLY_RECEIVED -> RECEIVED -> CLOSED
                     \-------------------------------------------> CLOSED
```

- 草稿可修改；提交后明细快照不可覆盖。
- 审批人与创建人职责分离；拒绝以 `CLOSED` 和必填审核意见记录，不删除采购事实。
- 每次收货锁定采购单及明细，校验版本和累计数量，再调用库存应用服务。
- 收货单、批次、批次流水、地点余额、库存流水、审计和 outbox 同事务提交。
- 收货幂等键与请求摘要绑定；同键同载荷返回原结果，同键异载荷返回 409。

## 数据库迁移

计划新增：

- `purchase_order`
- `purchase_order_item`
- `purchase_receipt`
- `purchase_receipt_item`
- `stock_batch`
- `stock_batch_movement`

既有 `stock_balance` 和 `inventory_movement` 不删除、不重算。迁移按现有地点/商品余额
创建 `MIGRATION_OPENING` 批次和期初批次流水，批次数量合计必须等于原地点库存。
历史数据不伪造供应商批号、生产日期、到期日期或单位成本。

## 索引与兼容

- 采购编号、收货编号、收货幂等键按租户唯一。
- 采购明细按采购单/商品索引；收货明细按采购明细索引。
- 批次按租户、地点、商品、到期日、状态建立 FEFO 查询索引。
- 批次业务流水按业务键唯一，禁止重复入库。
- 新表为 expand-only；V1/V2 和 M4-04 应用可忽略，不修改历史接口契约。

## 回滚

异常时关闭采购写入口并回退应用，保留新表和已产生的采购、收货、批次及流水。不得
删除收货单、修改期初批次或手工抹平批次与地点余额。只有在备份、依赖扫描、独立审批
和恢复演练后，才允许另建收缩迁移。

## 测试先行清单

1. 迁移、外键、检查约束、索引、权限和期初批次契约。
2. 采购状态非法跳转、申请人自审和过期版本。
3. 收货幂等重放、同键异载荷、部分收货、超收和并发收货。
4. 批次 FEFO、过期/冻结批次和批次合计复算。
5. 故障注入下采购、批次、地点余额、库存流水、审计和 outbox 全回滚。
6. 管理端桌面/窄屏、权限、错误处理和浏览器控制台。
