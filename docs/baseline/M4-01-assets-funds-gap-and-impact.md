## 2. 基线结论与文档冲突

### 2.1 基线要求

M4 必须交付：

1. 套餐产品、会员套餐实例、套餐余额快照和不可变核销/冲正流水。
2. 会员余额、赠送金和积分账户的余额快照与不可变账户流水。
3. 支付交易、退款申请/审批/执行和资产原路冲正。
4. 采购单、收货批次、批次库存和库存流水。
5. 支付通道适配边界与日终对账批次。
6. 幂等、版本、权限、审计、失败回滚和敏感数据保护。

M4 验收必须证明：

- 重复请求不会重复入账、扣减、核销、退款或收货。
- 退款通过独立退款交易和冲正流水恢复资产，不修改原支付金额和原资产流水。
- 套餐、账户和库存的余额快照可由不可变流水复算。
- 日终支付、退款和系统账汇总一致；差异可追踪、可处理且不能直接抹平。

### 2.2 API 文档缺口

`美容院店铺管理系统 API接口清单V1.1.docx` 的接口清单标题和正文均明确为
“M1-M3 接口清单”。它只列出退款入口和部分强制状态规则，没有定义 M4 的套餐、
账户、采购批次、支付通道和对账接口。

处理原则：

- 不修改或猜测既有 `/api/v1`、`/api/v2` 行为。
- M4 新能力使用 `/api/v3`，统一遵守现有 V3 响应、错误码、金额字符串、版本和
  `Idempotency-Key` 约定。
- 在实现前先以 `docs/architecture/api-contract-m4.md` 固化受控补充契约。
- 后续应把该补充契约同步回商业 API 文档的新版本，不能把原 V1.1 标记为已覆盖 M4。

## 4. 影响模块

### 4.1 `package` 新模块

- 拥有套餐产品、套餐项目版本、会员套餐实例和套餐流水。
- 套餐购买通过交易应用服务确认支付结果，不直接写支付私有表。
- 套餐核销必须关联 `service_record`，并通过服务应用服务校验会员、项目和完成状态。
- 冲正以新流水引用原核销流水；原核销事实不可覆盖或删除。

### 4.2 `account` 账户应用服务

- 从现有 `transaction` 私有方法中提取账户锁定、扣减、入账、冻结和冲正能力。
- 账户服务独占 `member_account` 与 `member_account_ledger` 写入。
- 交易和退款模块通过账户应用服务协作，不直接写账户私有表。
- 金额账户使用两位小数；积分使用零小数，均在服务端校验。

### 4.3 `transaction` 交易与退款

- 保留订单、支付和退款交易所有权。
- 退款申请增加稳定请求摘要，同键异载荷返回 `IDEMPOTENCY_CONFLICT`。
- 退款审批与退款执行分离，为外部通道保留 `PROCESSING/FAILED` 和可重试状态。
- 退款成功后调用账户、套餐、积分和后续提成模块的冲正服务；M5 提成未上线时只发布
  不含敏感数据的 `RefundCompleted` outbox 事件。
- 不修改原支付金额、原账户流水、原套餐流水或已完成服务事实。

### 4.4 `purchase` 采购模块

- 拥有采购单和采购明细的草稿、提交、审批、收货和关闭状态。
- 收货通过库存应用服务创建/增加批次余额及采购入库流水。
- 采购模块不得直接写 `stock_balance` 或 `inventory_movement`。
- 部分收货按独立收货幂等键处理，不能通过覆盖累计数量隐藏历史。

### 4.5 `inventory` 库存模块

- 继续独占库存地点、余额、冻结和不可变流水。
- 新增批次维度：批次号、供应商批号、生产/到期日期、单位成本、收到/可用数量和版本。
- 对批次商品按明确的 FEFO（先到期先出）策略分配；无效期商品按收货时间 FIFO。
- 现有无批次历史余额放入“迁移期初批次”，不伪造供应商批号或效期。

### 4.6 `reconciliation` 对账模块

- 拥有对账批次、通道汇总、系统汇总、差异和处理状态。
- 只读取交易应用服务公开的支付/退款查询，不直接修改支付、订单或资产流水。
- 差异处理写备注、责任人、证据引用和审计；如需业务修复，调用相应冲正服务。

### 4.7 三端与管理界面

- 管理端：套餐管理、会员套餐账、账户账、退款审核/执行状态、采购收货、库存批次和对账。
- 技师端：仅展示本人服务可用套餐并发起核销，不显示会员资金余额或退款权限。
- 会员端：查看本人套餐余额、核销历史、资金账户流水和退款进度。
- 沿用白色主题；权限由后端强制，前端隐藏按钮不能替代授权校验。

最终字段以测试和 Flyway 迁移评审为准；只允许向前扩展，不删除或重命名现有字段。

### 5.2 必要唯一约束与索引

- 套餐产品：租户内业务编号唯一；租户/状态/门店可售范围索引。
- 套餐实例：租户内实例编号唯一；租户/会员/状态/到期时间索引。
- 套餐流水：租户/实例/幂等键唯一；原流水引用索引；服务记录核销唯一约束。
- 退款：租户/幂等键唯一并保存请求摘要；外部退款号按通道唯一。
- 采购：租户内采购单号唯一；收货幂等键唯一。
- 库存批次：租户/地点/商品/内部批次号唯一；商品/到期时间/可用数量索引。
- 对账：租户/通道/账务日期唯一；差异状态索引。

### 5.3 状态

- 套餐产品：`DRAFT -> ACTIVE -> INACTIVE`
- 套餐实例：`ACTIVE -> FROZEN/EXHAUSTED/EXPIRED/CANCELLED`
- 采购单：`DRAFT -> SUBMITTED -> APPROVED -> PARTIALLY_RECEIVED -> RECEIVED/CLOSED`
- 退款：`PENDING -> APPROVED -> PROCESSING -> SUCCESS/FAILED`，或 `PENDING -> REJECTED`
- 对账批次：`PENDING -> RUNNING -> MATCHED/DIFFERENT -> RESOLVED/CLOSED`

任何终态更正均通过冲正、重开或追加处理记录完成，不直接覆盖历史。

### 5.4 权限

计划新增：

- `package:view`
- `package:manage`
- `package:writeoff`
- `package:reverse`
- `account:view`
- `account:manage`
- `refund:request`
- `purchase:view`
- `purchase:manage`
- `purchase:receive`
- `reconciliation:view`
- `reconciliation:manage`

`refund:approve` 继续复用。高风险动作要求后端门店/租户范围、角色权限、版本和审计同时通过。

## 6. 迁移、兼容与回滚

### 6.1 Expand

1. 新增表、可空扩展列、外键、检查约束和索引。
2. 新权限先创建，再按既有角色职责显式授权。
3. 旧应用仍可忽略新增表和可空列。
4. 新功能默认关闭，迁移与验证通过后按模块开启。

### 6.2 Migrate

- 旧 `care_package` 只映射为可选套餐产品草稿，不创建会员套餐实例。
- 现有会员账户和账户流水原样保留，不重算或覆盖历史余额。
- 现有地点库存余额按地点/商品生成“迁移期初批次”；批次数量合计必须等于原余额。
- 现有支付和退款保留；历史退款的请求摘要不回填伪造值，只对新写入强制。
- 所有回填按租户和门店分批、可重入，并记录批次和核对结果。

### 6.3 兼容

- `/api/v1`、`/api/v2` 行为不变；M4 使用 `/api/v3`。
- V2 交易页面继续可读现有订单/退款；新增字段只追加。
- 未切换外部通道时，微信/支付宝只保留现有兼容行为并明确标记为本地登记，
  不能宣称已完成生产通道支付。
- M4 账户服务上线后，旧交易服务通过应用服务适配，不允许出现第二套账户写入口。

### 6.4 回滚

- 应用回滚：关闭 M4 新入口，旧版本继续忽略新增结构。
- 数据回滚：不删除已经产生的套餐、账户、采购、库存批次、退款或对账流水。
- 迁移失败：停止发布，保留失败数据库，使用迁移前备份重建影子库后重新演练。
- 若必须物理 Contract，至少经过一个稳定发布周期、单独审批、导出归档和恢复演练。

## 7. 测试先行清单

### 7.1 套餐与账户

1. 同一核销幂等键同载荷稳定重放，不重复减次数；异载荷冲突。
2. 并发核销同一余额时最多一个成功，余额不为负。
3. 核销同时写余额快照、不可变流水和服务记录引用；任一步失败全部回滚。
4. 已完成核销不可删除/修改；冲正产生反向流水并恢复余额。
5. 冻结、过期、耗尽、非本人或跨店套餐不可核销。
6. 账户消费、充值、退款和冲正的快照可由流水复算。
7. 冻结账户不可扣款；不同账户类型的小数规则正确。

### 7.2 支付与退款

1. 退款相同幂等键同载荷重放；同键不同金额、支付或原因冲突。
2. 并发退款不能超过原支付可退金额。
3. 外部通道失败或超时不能把订单/退款伪装为成功。
4. 退款成功通过新流水恢复余额、套餐和积分，不修改原支付金额或原流水。
5. 任一资产冲正失败时退款成功状态、订单汇总和所有冲正整体回滚或保持可重试一致状态。
6. 申请人无审批权限；审批人越权门店、过期版本和重复审批均被拒绝。

### 7.3 采购与批次库存

1. 采购提交、审批、收货和关闭状态非法跳转被拒绝。
2. 收货幂等不会重复增加库存或批次。
3. 部分收货累计不超过采购数量；并发收货受版本和行锁保护。
4. 收货在同一事务写批次、余额、库存流水和采购收货记录。
5. 历史余额迁移到期初批次后，地点/商品汇总完全一致。
6. FEFO/FIFO 分配、效期和库存不足行为有确定性测试。

### 7.4 对账、权限和数据保护

1. 同一通道和账务日期只生成一个对账批次。
2. 支付、退款和通道汇总一致时为 `MATCHED`；差异只能追加处理记录。
3. 套餐、账户、采购、退款、对账的租户、门店和 SELF 越权全部返回 403/404。
4. 日志、审计、outbox 和对账文件不包含手机号、健康信息、证件、支付凭据或原始通道密钥。
5. 故障注入覆盖锁、库存、账户、套餐、退款通道、审计和 outbox。

## 8. 分片实施顺序与验收门禁

1. **M4-01 基线与影响**：完成本文和 M4 V3 契约补充。
