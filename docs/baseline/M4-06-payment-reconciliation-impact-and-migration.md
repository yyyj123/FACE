# M4-06 支付适配器、回调安全与对账影响及迁移方案

## 开工检查

- 当前阶段与任务：M4-06，支付适配器、回调安全、外部退款适配与日终对账。
- 输入：四份 V1.1 冻结基线、M4 差距矩阵、M4 API 补充契约、M4-05 已验收代码。
- 输出：支付通道边界、待确认支付、HMAC 回调验签与幂等、外部退款请求、
  对账批次/明细/处理记录、权限、V3 API、管理端和验收证据。
- 验收：外部通道未配置时不得记账成功；回调伪造和重放不得改变业务账；日终支付、
  退款和通道汇总可核对；差异只能追加处理记录，不能直接抹平。
- 前置门禁：M4-05 已通过；M4-06 通过前不得进入 M4-07。

## 影响模块

- `transaction`：订单与支付仍由交易模块拥有；外部支付创建为 `PENDING`，只有经过
  验签且幂等的成功回调才能推进支付、订单、库存、审计和 outbox。
- `payment` 适配边界：适配器只负责创建通道请求、验签、解析回调和发起退款，不直接
  写订单、支付、退款或资产表。
- `refund`：现金/余额继续使用 `LOCAL_LEDGER`；外部通道调用适配器，成功或失败结果
  由交易应用服务在受控事务中落账。
- `reconciliation`：拥有对账批次、差异明细和处理记录；通过公开查询读取支付/退款，
  不直接修改交易、订单、账户、套餐或库存私有表。
- `security`：支付回调是唯一免登录入口，仅以通道、时间戳、事件号、HMAC 签名和
  请求体摘要建立信任；管理接口仍要求租户、门店和权限。
- `admin-next`：新增“支付与对账”页面；沿用白色主题、标准表格/筛选/详情结构。

## 数据库、索引与状态

计划新增：

- `payment_callback_event`：保存通道事件号、载荷摘要、验签结果和处理结果；不保存
  原始支付凭据。
- `reconciliation_batch`：租户、门店、通道、账务日期、系统/通道汇总、状态和版本。
- `reconciliation_item`：按支付或退款业务号记录系统金额、通道金额与差异类型。
- `reconciliation_resolution`：只追加处理意见、证据引用、责任人和处理时间。

计划扩展：

- `payment_transaction`：`channel_code`、`channel_status`、`channel_request_no`、
  `channel_event_id`、`confirmed_at`。
- `refund_transaction`：复用既有 `execution_mode`、`external_refund_no`、
  `channel_status` 和失败字段。

唯一约束与索引：

- 回调事件：`(channel_code, channel_event_id)` 唯一，载荷摘要用于同事件异载荷拒绝。
- 对账批次：`(tenant_id, shop_id, channel_code, accounting_date)` 唯一。
- 对账明细：`(batch_id, business_type, business_no)` 唯一；按差异状态索引。
- 外部支付请求号：租户内通道请求号唯一；通道交易号按通道唯一。

状态：

- 支付：`PENDING -> SUCCESS/FAILED/CANCELLED`；终态不得由重复回调覆盖。
- 回调：`RECEIVED -> VERIFIED -> PROCESSED/REJECTED/IGNORED`。
- 对账：`PENDING -> RUNNING -> MATCHED/DIFFERENT -> RESOLVED -> CLOSED`。

## 权限与职责分离

- 新增 `reconciliation:view`：负责人、店长、财务可查看。
- 新增 `reconciliation:manage`：负责人、财务可创建、处理和关闭。
- 支付创建继续使用 `order:manage`；回调不使用员工身份，也不授予业务权限。
- 对账处理不能调用任意 SQL 调整账目；如需业务修复，必须进入对应退款/冲正流程。

## 兼容与迁移

- 迁移为 expand-only，不删除、不重命名现有列，不修改既有 Flyway 文件。
- 历史 `SUCCESS` 支付保持原样，新增通道字段为空；不伪造通道事件或回调时间。
- `/api/v1`、`/api/v2` 查询保持兼容；M4-06 新能力使用 `/api/v3`。
- `CASH`、`BALANCE` 保留本地账本语义；`CARD`、`WECHAT`、`ALIPAY` 无生产配置时
  返回 `DEPENDENCY_UNAVAILABLE`，不得生成成功支付或外部退款号。
- `SANDBOX` 仅在显式配置测试密钥时启用，用于隔离验收；界面和文档不得称其为生产通道。

## 回滚

- 应用回滚：关闭外部支付和对账入口；旧版本继续忽略新增结构。
- 数据回滚：保留已接收回调、支付、退款、对账批次、明细和处理记录，不执行物理删除。
- 已确认支付或退款通过正式冲正流程处理，禁止手工改回 `PENDING`。
- 迁移失败时停止发布，保留失败库，使用迁移前备份重建影子库后重演。

## 测试先行清单

1. 外部支付无配置时返回不可用，订单、支付、库存和审计均不改变。
2. 合法 HMAC 回调推进一次；重复同载荷稳定重放；同事件异载荷拒绝。
3. 时间戳过期、签名错误、通道不匹配和金额不匹配均不改变业务账。
4. 成功回调在同一事务更新支付、订单、库存、审计与 outbox；故障全部回滚。
5. 外部退款成功、失败和重试不重复冲正资产。
6. 同通道同门店同账务日期只生成一个批次；同键异汇总冲突。
7. 汇总相同时为 `MATCHED`；不同时生成可追踪差异明细。
8. 差异处理只追加记录；未匹配或未处理批次不能关闭。
9. 跨租户、跨门店和无权限访问被拒绝；日志不含密钥、原始凭据或客户敏感数据。
10. 迁移、索引、检查约束、兼容升级、真实 MySQL 和管理端桌面/窄屏全部通过。
