# M4 退款生命周期实现契约

## 模块边界

- `transaction` 拥有退款申请、审批、执行状态和支付/订单汇总。
- `packageaccount` 只通过公开应用服务完成会员余额退款和套餐冲正；交易模块不得直接
  写会员账户、套餐实例或其不可变流水。
- `outbox`、审计、支付/订单汇总与本地退款事实同事务提交。
- 控制器只负责认证、DTO、幂等摘要和稳定响应；V2/V3 路由统一委托
  `RefundApplicationService`。

## 状态机与职责分离

```text
PENDING ──批准──> APPROVED ──执行──> PROCESSING ──成功──> SUCCESS
   │                    │                         └─失败──> FAILED
   └──────拒绝──────────> REJECTED
```

- `refund:request` 创建申请；同一申请幂等键同载荷返回原记录，同键异载荷返回 409。
- `refund:approve` 审批；申请人不得审批自己的申请。
- `refund:execute` 执行；执行使用独立幂等键和请求摘要。
- 已完成或已拒绝退款不可再次审批或执行；版本冲突拒绝覆盖。
- `created_by`、`approved_by`、`executed_by` 分别保留申请、审批和执行责任人。

## 本地账务与外部通道

本地现金/余额执行：

1. 锁定退款、支付和订单。
2. 校验状态、可退金额、订单/支付一致性和版本。
3. 余额支付调用会员账户应用服务追加 `ORDER_REFUND` 流水。
4. 完全未使用的套餐订单全额退款调用套餐应用服务追加反向流水并取消实例。
5. 更新支付累计退款和订单状态，写审计与 `RefundCompleted` outbox。

银行卡、微信、支付宝属于外部适配器。当前无生产通道凭据，因此执行返回 503，
退款保持 `APPROVED`；不得生成外部退款号、不得改为 `SUCCESS`、不得提前冲正本地账务。
M4-05 接入通道后复用同一状态机和执行幂等字段。

## 查询范围与三端呈现

- 管理端 `/transactions`：显示申请、审批、执行三个阶段；外部退款显示“外部通道待配置”。
- 会员端 `/appointments`：只查询本人退款，显示已申请、已审核、已退款三阶段进度。
- 技师端不查询退款资金数据，也不显示审批或执行入口。
- 管理员查询要求门店 `order:view`；会员 SELF 缺失或跨会员查询返回 404，避免泄露。

## 兼容与错误处理

- V3 使用 `/api/v3/payments/{id}/refunds`、`/refunds/{id}/decision`、
  `/refunds/{id}/execute` 和 `/members/{id}/refunds`。
- V2 原申请/审批路由保留并委托同一应用服务；审批不再隐式完成资金退款。
- 外部依赖未配置返回 503；状态/余额/版本冲突返回 409；越权返回 403 或隐藏式 404。
- 日志、审计和 outbox 不记录手机号、健康信息、支付凭据或原始令牌。
